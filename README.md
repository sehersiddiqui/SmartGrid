# ⚡ GridMind — Smart Energy Management (Intelligent Systems)

**Forecast → Optimize → Control → Evaluate.** A research-style smart-building energy management system.

## What is implemented

- Procedural, seeded smart-building data generation (clearly labeled synthetic) and an optional public UCI household electricity-data loader.
- Time-series preprocessing, missing-value handling, robust outlier treatment, cyclical calendar features, lags, rolling statistics, and chronological train/validation/test splits.
- PyTorch LSTM load forecasting with train-only normalization and MAE/RMSE/MAPE evaluation; persistence baseline included.
- Optional solar forecasting and empirical residual uncertainty intervals.
- DEAP genetic algorithm for day-ahead battery scheduling, with energy cost, peak, comfort, battery throughput and state-of-charge constraints represented in fitness.
- Gymnasium custom building simulator; Stable-Baselines3 PPO training and inference when installed.
- Fuzzy comfort/priority logic, rule-based baseline, no-optimization baseline, GA-only, PPO-only and hybrid evaluation pathways.
- Streamlit dashboard, Plotly charts, SQLite experiment logging, and optional MQTT telemetry adapter.
- Jupyter/IPython notebooks for each research stage, tests, and environment setup.

> **Research integrity:** synthetic data are generated from equations and seeded random processes, not copied/hard-coded sample rows. If the UCI data option is used, it is real household electricity data; it does not itself provide all building/weather/occupancy fields, so auxiliary fields remain simulated and are marked as such. All reported results should be generated by running experiments on your machine. No savings percentage is guaranteed in advance.

## Architecture

```text
Public or procedurally generated data
      ↓
Acquisition + preprocessing + chronological split
      ↓
PyTorch LSTM forecast ──→ residual-based uncertainty scenarios
      ↓
DEAP GA day-ahead battery schedule
      ↓
PPO policy + current observations + GA schedule
      ↓
Gymnasium building simulator (HVAC, battery, EV, lighting)
      ↓
Reward/cost feedback ──→ evaluation and SQLite logs
      ↓
Streamlit dashboard (forecast, schedule, controls, metrics, comparisons)
```

## Quick start (Python 3.10–3.12 recommended)

```bash
# 1. Create and activate a virtual environment
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate

# 2. Install core + optional research dependencies
python -m pip install --upgrade pip
pip install -r requirements.txt

# 3. Launch the dashboard
streamlit run 09_dashboard/app.py

# 4. Or run the notebooks
jupyter lab
```

PyTorch installation can vary by CPU/GPU; if `pip install -r requirements.txt` fails on PyTorch, install the appropriate build from the official PyTorch selector and then rerun the requirements installation. PPO is optional at runtime: if Stable-Baselines3 is absent, the dashboard still supports the rule-based and GA demonstrations and explains that PPO training is unavailable.

## Recommended run order

1. `notebooks/01_data_and_preprocessing.ipynb`
2. `notebooks/02_lstm_forecasting.ipynb`
3. `notebooks/03_genetic_optimization.ipynb`
4. `notebooks/04_environment_and_ppo.ipynb`
5. `notebooks/05_evaluation_and_uncertainty.ipynb`

Or run `python run_experiment.py --days 30 --seed 42` for a compact end-to-end experiment. First run may train a small LSTM; use `--epochs 5` for a quick smoke test. For credible conclusions, increase training days/epochs and run multiple seeds.

## Public data option

The optional UCI loader downloads the Individual Household Electric Power Consumption dataset from the UCI Machine Learning Repository. It is a household dataset, not a commercial building dataset. Use `load_uci_household()` in a notebook, aggregate the global active power series to hourly observations, and document that weather, occupancy, solar and tariffs are simulated auxiliary covariates. The default app uses generated synthetic data so it runs offline and does not unexpectedly download a large file.

## Objective and metrics

The simulator minimizes a composite operating cost:

`J = electricity cost + peak penalty + comfort penalty + battery degradation penalty + unmet service penalty`

Forecasting: MAE, RMSE, MAPE (MAPE excludes near-zero denominators).
Energy management: total cost, peak grid demand, grid energy, comfort degree-hours, battery throughput, cost saving and peak reduction versus the same-day baseline.

## Notes on modelling assumptions

- The custom environment is an educational simulator, not a calibrated EnergyPlus building model or a safety-certified building controller.
- Tariff schedules, solar, occupancy and thermal dynamics are configurable simulated assumptions unless explicitly sourced from measurements.
- Battery actions are clipped to SOC and power limits; comfort is penalized, not ignored.
- The PPO policy is not trained automatically on every dashboard refresh. Train once, save the model, then load it for inference.
- Results from short synthetic experiments are demonstrations, not evidence of real-world savings. Evaluate multiple seeds and compare identical weather/load traces across controllers.
